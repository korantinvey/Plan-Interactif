/* ============================================================ 16. L'invitation à installer le plan Le plan public s'installe : ajouté à l'écran d'accueil, il s'ouvre d'un geste, en plein écran, et se consulte sans réseau une fois ouvert (`outils/pwa.js`, `_sw.js`). Une fenêtre qui interrompt ne s'ajoute pas d'elle-même à un salon déjà en ligne. Elle interrompt, et ce sont ses conditions qui en font une proposition plutôt qu'une réclame. Toutes doivent tenir : — le plan public, et lui seul : la page qui porte le manifeste. Ni l'administration ni la démonstration figée n'ont rien à installer ; — ouvert dans un navigateur : lancé depuis l'écran d'accueil, le plan est déjà installé, et dans le cadre d'un site tiers ce n'est pas à nous de proposer quoi que ce soit. La porte se lit comme pour la mesure ; — sur un téléphone ou une tablette : c'est là que le plan sert au salon. Sur un ordinateur, l'application n'apporte qu'une fenêtre sans barre d'adresse, rien qui vaille d'interrompre qui prépare sa visite ; — dès l'ouverture, mais jamais par-dessus ce qu'on fait : le plan affiché, la fenêtre suit, sauf si autre chose occupe l'écran — la fiche d'un stand ouverte par un lien, un parcours partagé, un doigt posé, une saisie. Reste celui qui l'a installée et revient par le navigateur : un lien suivi depuis un message, un code relu à l'entrée, un onglet resté ouvert de la veille. Il a l'application, et n'en profite pas — le plan s'ouvre dans un onglet parmi d'autres, barres comprises, et tombera avec le réseau. Sur Android, la page apprend du système que l'application est posée, et sait l'ouvrir : le raccourci qu'y pose Chromium est un paquet enregistré comme celui qui ouvre les adresses du site, et une intention le réveille. Elle l'affirme donc, et un bouton y mène. iOS n'a ni l'un ni l'autre — rien n'y dit qu'une application existe, rien ne l'y ouvre, et son stockage est séparé de celui du navigateur. Ce que la page sait du visiteur s'y arrête à ce qu'il a répondu ici : la fenêtre s'adresse donc à qui a lu les trois gestes et dit les avoir compris — le seul à qui l'icône puisse parler — et se borne à la lui suggérer. Un bouton qui ne tiendrait pas parole, ou une fenêtre qui affirmerait ce qu'elle ignore, valent moins que rien. Deux fenêtres, et pas une troisième : rien ne se dit dans la foulée de l'installation. Une fenêtre y annonçait l'application posée et offrait de l'ouvrir — trois fenêtres d'affilée sur Android, pour l'installation, le constat, puis le rappel, quand le visiteur n'en demandait qu'une. Le constat était le plus creux des trois : il apprenait au visiteur ce qu'il venait lui-même de faire, et son bouton doublait celui du rappel. Ce qui reste dit donc chaque chose une fois — d'abord installez, puis ouvrez —, et le navigateur annonce l'installation à sa façon, qui suffit. Le « puis » est court, et c'est voulu : l'installation efface la marque du jour au lieu de la poser, si bien que le premier rechargement qui suit ramène le rappel, son bouton avec. Le taire jusqu'au lendemain aurait laissé sans rien celui qui vient de poser l'icône et revient au navigateur — c'est-à-dire justement celui à qui le constat parlait. ============================================================ */ /* Le plan affiché, un instant pour qu'il se peigne : une fenêtre ouverte dans la même image que lui se poserait sur un écran encore vide, et le visiteur ne saurait pas ce qu'on lui propose d'installer. */ const INSTALL_ACCUEIL = 800; /* Après un geste, un temps sans geste : on ne se glisse pas sous un doigt qui fait glisser le plan, ni entre deux frappes. */ const INSTALL_CALME = 1500; /* Deux refus, puis plus rien : une troisième fois, ce ne serait plus proposer. */ const INSTALL_REFUS = 2; /* Dix secondes avant de rappeler l'application installée : le temps de reconnaître le plan et de faire un geste ou deux — assez pour sentir ce qu'on gagnerait à l'ouvrir en grand, trop peu pour avoir fini ce qu'on venait faire et n'avoir plus rien à y changer. */ const RAPPEL_DELAI = 10000; /* Ce qu'on laisse à l'application pour prendre la main. La page encore là passé ce délai, c'est que rien ne s'est ouvert. */ const RAPPEL_LANCEMENT = 1500; const reglageInstallation = () => conf("_installation"); const invitationVoulue = () => reglageInstallation().active === true; /* La page qui s'installe est celle qui porte le manifeste. Relevé plutôt que redit : c'est `outils/genere.js` qui décide quelle page le porte, et ce module suit sans rien savoir de plus. Le sélecteur s'écrit sans guillemets, et ce n'est pas un détail : la construction reconnaît la page installable à la chaîne de son lien, et ce module part dans les trois pages du plan — écrit entre guillemets, il les aurait toutes annoncées installables. */ const INSTALL_PAGE = !!document.querySelector("link[rel=manifest]"); const UA_INSTALL = navigator.userAgent || ""; /* iPadOS se présente en Mac depuis sa version 13 : seul l'écran tactile le trahit. */ const IOS_INSTALL = /iPhone|iPad|iPod/.test(UA_INSTALL) || (/Macintosh/.test(UA_INSTALL) && navigator.maxTouchPoints > 1); /* Android, hors vue web d'une application — celle-ci se reconnaît à sa marque `wv`, et n'installe rien : elle n'a ni menu à ouvrir ni application à réveiller. Les deux choses qu'Android sait faire et qu'iOS ne sait pas tiennent à ce même test, et n'en font donc qu'un. */ const ANDROID_INSTALL = /Android/.test(UA_INSTALL) && !/; wv\)/.test(UA_INSTALL); /** * Un téléphone ou une tablette : le pointeur principal est un doigt. * * La largeur de l'écran ne le dirait pas — une tablette en paysage est plus * large que bien des portables — et un portable à écran tactile se pilote * d'abord au pavé : il reste un ordinateur. */ function auDoigt(){ try { return matchMedia("(pointer: coarse)").matches; } catch (e) { return false; } } /* Tout ce qui ne bouge pas d'ici la fin de la page se juge une fois : ailleurs qu'au doigt, dans un navigateur, sur le plan public, le module ne pose pas même un écouteur. */ /* Une borne n'a rien à installer : l'écran est déjà à demeure, et le visiteur qui passe devant n'emportera pas la tablette du salon. */ const INSTALL_POSSIBLE = INSTALL_PAGE && auDoigt() && supportMesure() === "web" && !BORNE; /* ------------------------------------------------------------ Le nom que l'appareil retiendra ------------------------------------------------------------ */ /** * Nommer et habiller l'application du salon qu'on regarde. * * Le manifeste porte déjà les deux : la page y nomme le salon, le relais va * chercher son nom, ses icônes et l'écrit — « Plan SMCL by Event2Plan », ou ce * que le salon a choisi (`outils/pwa.js`, `src/index.mjs`, * `_application.html`). iOS, lui, ne lit pas le manifeste pour l'écran * d'accueil : il prend `apple-mobile-web-app-title` et `apple-touch-icon`, des * balises écrites avec la page, donc avant que le salon soit connu — l'icône * se posait sous « Plan », et sous la marque du produit, quel que soit le * salon. Les deux sont relues au moment de l'ajout : les corriger dès les * données arrivées suffit. * * Le nom écrit par l'exploitant l'emporte, et à défaut le salon seul, comme * dans le manifeste : sous une icône, la place est d'une douzaine de signes, * et c'est le salon qu'on y cherche. * * L'icône posée est celle des deux que le système ne peut pas abîmer : la * version opaque, faite pour être rognée. iOS ne garde pas la transparence * d'une icône d'écran d'accueil — il la remplit de noir — et un logo sombre * sur fond transparent y disparaissait. */ function nommeApplication(nom){ const balise = document.querySelector("meta[name=apple-mobile-web-app-title]"); const choisi = appDuSalon().nom || nom; if (balise && choisi) balise.content = choisi; const lien = document.querySelector('link[rel="apple-touch-icon"]'); const sienne = iconeDeLApplication(true); if (lien && sienne) lien.href = sienne; } /* ------------------------------------------------------------ Ce que le visiteur a répondu ------------------------------------------------------------ */ /* Rangé sous le nom du salon : chaque salon s'installe comme une application à part (`outils/pwa.js`), et avoir refusé l'un ne dit rien de l'autre. Ce que le salon voulait à la dernière visite y est gardé aussi — voir `beforeinstallprompt`, plus bas. */ const CLE_INSTALL = "plan-installation:" + SLUG; function reponsesInstallation(){ try { return JSON.parse(localStorage.getItem(CLE_INSTALL) || "{}") || {}; } catch (e) { return {}; } } function retientInstallation(change){ try { localStorage.setItem(CLE_INSTALL, JSON.stringify(Object.assign(reponsesInstallation(), change))); } catch (e) {} } /* Le jour du visiteur, et non celui du serveur : « une fois par jour » se compte à sa montre. */ const jourInstallation = () => new Date().toDateString(); /** A-t-on déjà assez proposé ? */ function invitationEcartee(){ const r = reponsesInstallation(); return r.installe === true || r.compris === true || (r.refus || 0) >= INSTALL_REFUS || r.vue === jourInstallation(); } const refuseInstallation = () => retientInstallation({ refus: (reponsesInstallation().refus || 0) + 1 }); /* ------------------------------------------------------------ Comment ce navigateur installe ------------------------------------------------------------ */ /* L'événement par lequel Chromium dit le plan installable, gardé pour le moment choisi : c'est lui qui installe d'un clic. */ let INSTALL_NATIVE = null; /** * La façon d'installer que ce navigateur connaît, s'il en connaît une. * * « bouton » : Chromium a jugé le plan installable, et gardé de quoi le faire * d'un clic. Tant que son événement n'est pas venu, il se tait — le plan y est * déjà installé, ou n'y est pas encore installable — et la fenêtre attend avec * lui : expliquer l'installation à qui a déjà l'application, ce serait lui * dire qu'on ne la voit pas. * * « partage » : iOS et iPadOS, où tout navigateur installe depuis la feuille * de partage du système, et n'en dit rien à la page. Les vues web des * applications — un lien ouvert depuis un réseau social — n'ont pas cette * entrée : elles ne se présentent pas en Safari, et on s'y tait. * * « menu » : les autres navigateurs d'Android, Firefox en tête, qui installent * depuis leur menu sans rien en dire non plus. La vue web d'une application * n'installe rien, elle, et se reconnaît à sa marque `wv`. */ function faconInstallation(){ if (INSTALL_NATIVE) return "bouton"; if ("onbeforeinstallprompt" in window) return null; if (IOS_INSTALL) return /Safari\//.test(UA_INSTALL) ? "partage" : null; if (ANDROID_INSTALL) return "menu"; return null; } /* ------------------------------------------------------------ L'application déjà posée sur l'appareil ------------------------------------------------------------ */ /** * Là où un bouton peut vraiment ouvrir l'application. * * Android, et lui seul. Chromium y installe le plan comme un paquet que le * système enregistre parmi ceux qui savent ouvrir les adresses du site : une * intention lui est alors remise, et il s'ouvre (`lanceApplication`). iOS n'a * rien d'équivalent — ni lien ni interface ne passent de l'onglet à * l'application, et la page ne sait même pas qu'elle existe. */ const LANCEMENT_POSSIBLE = ANDROID_INSTALL; /** L'application est-elle sur cet appareil, pour autant qu'on le sache ? */ const appliInstallee = () => reponsesInstallation().installe === true; /** * Ce que le système sait de l'application, et que la page ne saurait pas. * * Le plan retient l'installation qu'il a vue passer (`appinstalled`), mais une * mémoire ne se corrige pas d'elle-même : l'application retirée le lendemain, * il continuerait d'inviter à ouvrir une icône qui n'est plus là. * `getInstalledRelatedApps()` répond pour de bon — c'est à cela que sert le * `related_applications` où l'application se nomme elle-même * (`outils/pwa.js`). * * Elle ne sert qu'à reconnaître, jamais à démentir. Une liste vide ne dit pas * qu'il n'y a rien : l'adresse du manifeste sous laquelle l'application a été * posée n'est pas toujours celle que la page demande — installée depuis * `?plan=`, relue depuis l'adresse nue du même salon — et le démenti * porterait alors sur une application bien présente. * * Ce qui dément, c'est `beforeinstallprompt` : Chromium ne l'émet pas pour une * application déjà posée, et le recevoir vaut donc constat qu'elle ne l'est * plus. Le signal est direct, là où la liste vide n'était qu'une inférence. */ function verifieApplication(){ if (!navigator.getInstalledRelatedApps) return; navigator.getInstalledRelatedApps().then(liste => { if (connaitLApplication(liste)) retientInstallation({ installe: true }); essaieInvitation(); }, () => {}); } /** Ce que le système dit d'une application posée, quand il en dit quelque * chose : la plateforme qu'il nomme est celle du manifeste. */ const connaitLApplication = (liste) => (liste || []).some(a => a && a.platform === "webapp"); /** * L'adresse que l'application ouvre : son adresse de départ, qui est aussi tout * son territoire. * * Composée et non recopiée, comme le fait le relais pour le manifeste * (`src/index.mjs`) : ce qui part au système ne doit porter que le salon — ni * jeton de courriel, ni ancre, ni paramètre de passage. Et ce doit être ce * chemin-là, le seul que l'application revendique : l'intention lancée sur une * adresse hors de sa portée ne trouverait personne pour la prendre. */ function adresseApplication(){ return SLUG ? cheminDuSalon(SLUG) : location.pathname; } /** * Passer le visiteur du navigateur à l'application. * * Une adresse ordinaire n'y suffirait pas : elle reste dans l'onglet, un * navigateur ne se dessaisissant jamais d'un site qu'il sait afficher. * `intent://` s'adresse au système par-dessus lui, et le système, lui, connaît * le paquet posé à l'installation. Sans le nommer : Chromium le fabrique sous * un nom haché, indevinable, et le système sait de lui-même qui ouvre les * adresses de ce site. * * Aucune adresse de repli non plus : sans preneur, l'intention retombe et il * ne se passe rien — ce qui vaut mieux qu'un plan rechargé sous les yeux du * visiteur. Le silence se lit un instant plus tard, à la page toujours là, et * on lui dit alors où est l'icône. Une fois pour toutes : un bouton qui n'a * pas ouvert l'application une fois ne l'ouvrira pas davantage la prochaine. */ function lanceApplication(){ const cible = new URL(adresseApplication(), location.href); try { location.href = "intent://" + cible.host + cible.pathname + cible.search + "#Intent;scheme=" + cible.protocol.slice(0, -1) + ";action=android.intent.action.VIEW" + ";category=android.intent.category.BROWSABLE;end"; } catch (e) {} setTimeout(() => { // la page effacée, c'est que l'application a pris la main : rien à dire if (document.visibilityState !== "visible") return; retientInstallation({ rappelClos: true }); if (!$("modale").classList.contains("open")) ouvreRetrouve(false); }, RAPPEL_LANCEMENT); } /** * Ce que le rappel peut proposer sur cet appareil, s'il peut proposer quelque * chose. * * « ouvrir » : l'application est là, et on sait l'ouvrir. Android et lui seul, * où la page apprend du système l'une et l'autre chose. * * « suggerer » : iOS, où elle n'apprend ni l'une ni l'autre. Rien n'y dit * qu'une application est posée, rien ne l'y ouvre, et le stockage de * l'application y est séparé de celui du navigateur — ce que la page sait du * visiteur s'arrête donc à ce qu'il a répondu ici. L'installation y est impossible, ou la page ne saurait pas * à qui elle parle. */ function faconRappel(){ if (LANCEMENT_POSSIBLE) return appliInstallee() ? "ouvrir" : null; if (IOS_INSTALL && faconInstallation() === "partage" && reponsesInstallation().compris === true) return "suggerer"; return null; } /** A-t-on déjà assez rappelé ? */ function rappelEcarte(){ const r = reponsesInstallation(); return r.rappelClos === true || (r.rappelRefus || 0) >= INSTALL_REFUS || r.rappelVue === jourInstallation(); } const refuseRappel = () => retientInstallation({ rappelRefus: (reponsesInstallation().rappelRefus || 0) + 1 }); /* ------------------------------------------------------------ Le moment ------------------------------------------------------------ */ /* L'instant du dernier geste — zéro tant qu'il n'y en a eu aucun — et les doigts encore posés : un glissement qui dure plus que le calme exigé n'a pas de geste nouveau à signaler, mais n'est pas fini pour autant. */ let installGeste = 0; const installDoigts = new Set(); let installMinuteur = null, installFini = !INSTALL_POSSIBLE; /* L'instant où le plan est vraiment sous les yeux — zéro tant qu'il ne l'est pas. C'est de là que se comptent les dix secondes du rappel, et non de l'appel qui l'amène : un geste, un onglet repris ou une réponse tardive du système rappelaient l'application avant l'heure. */ let installAccueil = 0; function relanceInvitation(ms){ clearTimeout(installMinuteur); installMinuteur = setTimeout(essaieInvitation, Math.max(0, ms)); } function gesteInstallation(){ installGeste = performance.now(); relanceInvitation(INSTALL_CALME); } function doigtPose(e){ installDoigts.add(e.pointerId); gesteInstallation(); } function doigtLeve(e){ installDoigts.delete(e.pointerId); gesteInstallation(); } // un onglet ouvert en arrière-plan attend qu'on y vienne, et l'accueille alors function vueInstallation(){ if (document.visibilityState === "visible") relanceInvitation(INSTALL_ACCUEIL); } /** * Le plan est affiché : l'invitation peut venir. Appelée par `demarre`, sur * toutes les pages du plan — ailleurs que sur le plan public au doigt, elle * n'a rien à faire et le dit tout de suite. */ function accueilleInvitation(){ /* Après la proposition de visite guidée (`TUTO_DELAI`), qui se propose au même moment : elle renonce si l'écran est pris, quand l'invitation, elle, attend qu'il se libère. Passer la seconde ne coûte à l'invitation qu'un instant ; passer la première aurait coûté la visite guidée. */ /* Et après le générique du sponsor, pour la même raison qu'elle : ce qui se pose sur le logo le fait payer pour l'écran d'un autre (`_sponsor.html`). */ if (installFini) return; installAccueil = performance.now() + resteSponsor(); /* Le rappel de l'application installée prend son temps à lui : il n'a rien à proposer d'urgent, et ce qu'il vante — le plein écran, le hors-ligne — ne se regrette qu'une fois le plan sous les yeux. */ relanceInvitation(appliInstallee() ? RAPPEL_DELAI + resteSponsor() : TUTO_DELAI + INSTALL_ACCUEIL + resteSponsor()); } /** * Ce qui retient la fenêtre maintenant : un doigt posé, une autre fenêtre, un * tiroir ouvert, un stand qu'on vise pour un itinéraire, une saisie en cours. * * C'est ce qui l'empêche de passer devant la raison de la venue : un lien vers * un stand ouvre sa fiche, un parcours partagé sa fenêtre, et l'invitation * attend qu'on les ait refermés. L'attente en tient déjà compte ; ceci rattrape le cas où il reparaît entre-temps — une borne remise au repos. */ if (resteSponsor()) return true; // une visite guidée en cours est un geste en train de se faire, sur toute sa durée if (TUTO) return true; if (["detail", "parcours", "itineraire"].some(id => { const t = $(id); return t && t.classList.contains("open"); })) return true; const v = $("viseur"); if (v && !v.hidden) return true; const f = document.activeElement; return !!f && /^(INPUT|TEXTAREA|SELECT)$/.test(f.tagName); } function finInvitation(){ installFini = true; clearTimeout(installMinuteur); removeEventListener("pointerdown", doigtPose, true); removeEventListener("pointerup", doigtLeve, true); removeEventListener("pointercancel", doigtLeve, true); removeEventListener("keydown", gesteInstallation, true); document.removeEventListener("visibilitychange", vueInstallation); } /** * Ouvre la fenêtre si tout le permet, ou dit ce qui la relancera. * * Appelée à l'affichage du plan, à chaque geste un instant après, au retour * sur un onglet caché, quand Chromium annonce le plan installable, et quand le * système a dit si l'application est là. Tout ce qui l'empêche pour de bon — * le réglage éteint, une réponse déjà donnée — arrête l'attente ; ce qui ne * l'empêche que pour l'instant la laisse à l'appel suivant. * * Deux fenêtres, jamais les deux : ou le plan n'est pas installé et on propose * de l'installer, ou il l'est et on propose de l'ouvrir. C'est la même attente * qui les porte, et les mêmes égards qui les retiennent — seuls le délai, les * conditions et les compteurs diffèrent. */ function essaieInvitation(){ // onglet caché : personne à inviter, le retour sur la page relancera if (installFini || document.visibilityState !== "visible") return; // le réglage arrive avec les données : avant elles, rien ne dit s'il est voulu if (!DATA) return; const voulue = invitationVoulue(); /* Retenu pour la visite suivante, où l'événement de Chromium peut précéder les données : il devra savoir sans elles s'il est attendu. */ if (reponsesInstallation().voulue !== voulue) retientInstallation({ voulue }); if (!voulue) return finInvitation(); /* Ce que le rappel aurait à proposer ici — rien, et c'est l'invitation qui reprend la main. Une application installée qu'on ne saurait ni ouvrir ni suggérer n'a pas de fenêtre : `invitationEcartee` se tait déjà pour elle. */ const rappel = faconRappel(); if (rappel ? rappelEcarte() : invitationEcartee()) return finInvitation(); if (rappel){ // le plan pas encore affiché, ou pas depuis assez longtemps : on repasse if (!installAccueil) return; const reste = installAccueil + RAPPEL_DELAI - performance.now(); if (reste > 0) return relanceInvitation(reste); } /* Chromium n'a pas encore annoncé le plan installable : son événement relancera. Il vient d'ordinaire dès le chargement, mais Chrome peut aussi attendre un premier geste et un peu d'usage — la fenêtre attend avec lui, puisqu'elle n'aurait rien à proposer sans. */ const facon = rappel ? null : faconInstallation(); if (!rappel && !facon) return; const calme = installGeste ? INSTALL_CALME - (performance.now() - installGeste) : 0; if (calme > 0) return relanceInvitation(calme); if (invitationRetenue()) return; finInvitation(); if (rappel) ouvreRappel(rappel, false); else ouvreInvitation(facon, false); } if (INSTALL_POSSIBLE){ addEventListener("beforeinstallprompt", e => { /* Le plan est installable : c'est donc qu'il n'est pas installé. Un `installe` resté d'une application retirée depuis condamnait tout — `invitationEcartee` se taisant pour une application posée, le plan ne proposait plus ni de l'installer ni de l'ouvrir, et rien ne venait jamais le détromper. */ if (appliInstallee()) retientInstallation({ installe: false }); /* Retenu, l'événement retire le bandeau que Chrome aurait posé en bas de l'écran : la fenêtre en tient lieu. Réglage éteint, il passe — le navigateur garde sa manière de proposer, qui n'a rien à nous demander. Il peut précéder les données. On se fie alors à ce que ce salon voulait à la visite précédente, et, faute d'en avoir eu une, on le garde — au pire, le bandeau du navigateur attend une visite de plus. */ const voulue = DATA ? invitationVoulue() : reponsesInstallation().voulue !== false; if (!voulue) return; e.preventDefault(); INSTALL_NATIVE = e; essaieInvitation(); }); /* Installé — par la fenêtre ou par le menu du navigateur, peu importe : on ne le proposera plus. */ addEventListener("appinstalled", () => { INSTALL_NATIVE = null; /* L'installation rouvre la question du rappel, et l'ouvre entièrement : ce qui en avait été refusé l'avait été d'une application d'avant, retirée depuis, et la journée ne se garde pas non plus.
